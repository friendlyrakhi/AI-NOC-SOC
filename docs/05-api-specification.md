# 05 — API Specification

The authoritative contract is the OpenAPI 3.1 document generated by FastAPI (`/api/v1/openapi.json`) and committed to `backend/openapi/openapi.json`. CI fails if the code and the committed spec diverge. This document defines conventions and the endpoint inventory.

## 1. Conventions

| Topic | Convention |
|-------|------------|
| Base path | `/api/v1` (URI major versioning; additive changes only within v1) |
| Tenant scoping | From the token's `tid` claim. **No tenant ID in paths** (except platform admin endpoints under `/api/v1/platform/tenants/{tenant_id}`). |
| Auth | `Authorization: Bearer <jwt>` (from BFF) or `Authorization: Bearer nsk_<key>` (API key). |
| Content | `application/json; charset=utf-8`; timestamps RFC 3339 UTC; IDs UUIDv7 strings. |
| Pagination | Cursor-based: `?limit=50&cursor=<opaque>` → `{ "items": [...], "next_cursor": "...", "has_more": true }`. Max `limit` = 200. |
| Filtering | `?status=new,acknowledged&severity=high,critical&since=...&until=...&q=<text>&asset_id=...` (allowlisted fields per resource). |
| Sorting | `?sort=-last_seen,severity` (allowlisted). |
| Concurrency | Responses include `ETag: "<version>"`; mutations require `If-Match`, and a stale ETag returns `412`. |
| Idempotency | `Idempotency-Key` header required on POSTs that create resources or trigger actions; stored 24 h per tenant + key. |
| Errors | RFC 9457 `application/problem+json`: `{type, title, status, detail, instance, code, trace_id, errors?[]}`. |
| Rate limits | `RateLimit-Limit`, `RateLimit-Remaining`, `RateLimit-Reset` headers; `429` with `Retry-After`. |
| Tracing | Accepts/returns W3C `traceparent`; `X-Request-Id` echoed. |
| Live updates | SSE: `GET /api/v1/stream?topics=alerts,incidents:{id}`; events: `alert.upserted`, `incident.changed`, `timeline.appended`, `approval.requested`, `connector.health`. |
| Permissions | Every operation documents `x-required-permission` in OpenAPI. |
| Sandbox labeling | Resources derived from sandbox connectors carry `"provenance": {"mode": "sandbox", ...}`. |

### Standard error codes (`code` field)
`auth.invalid_credentials`, `auth.mfa_required`, `auth.step_up_required`, `authz.forbidden`, `tenant.not_member`, `resource.not_found`, `resource.version_conflict`, `validation.failed`, `rate_limited`, `idempotency.conflict`, `connector.mode_not_allowed`, `action.execution_disabled`, `action.approval_required`, `action.self_approval_forbidden`, `ai.budget_exceeded`, `ai.provider_unavailable`, `ai.insufficient_evidence`, `killswitch.engaged`.

## 2. Endpoint inventory

> **P1 status:** sections 2.1, 2.2 and 2.11 are implemented, plus the MSP endpoints `GET/POST /customers`, `GET/POST /delegations`, `POST /delegations/{id}/revoke`, `GET /aggregate/customers`, `GET /aggregate/activity` and `POST /auth/invitations/accept`. The committed contract is `backend/openapi/openapi.json` (CI fails on drift). Conventions **not yet implemented** (planned with the first resources that need them, P2/P3): `ETag`/`If-Match`, `Idempotency-Key`, `RateLimit-*` headers (only sign-in is rate limited, with `429` + `Retry-After`), and cursor pagination (the audit log pages with `?before=<id>`).

Legend: **Perm** = required permission. (P#) = phase delivered.

## 3. Webhook contract (inbound)

```
POST /api/v1/ingest/webhooks/{instance_id}
X-NocSoc-Timestamp: 1763287200
X-NocSoc-Nonce: 7b3f…
X-NocSoc-Signature: v1=hex(HMAC_SHA256(secret, timestamp + "." + nonce + "." + raw_body))
```
Rules: body ≤ 1 MB (configurable), timestamp within ±300 s, nonce unique per instance for 10 min, JSON depth ≤ 32, 600 requests/min per instance. Responses are `202` (accepted), `401` (signature; also for unknown or disabled instances, so existence is not revealed), `409` (replay), `413` (size), `422` (depth or unrecognized payload) or `429`. The tenant is taken from the instance record, never from the request. For vendors with native signing schemes, a connector-specific verifier from the SDK is used instead.

## 4. Outbound integration events (to ServiceNow & generic webhooks)

The platform emits signed outbound webhooks (same signature scheme) for `incident.created/updated/resolved` to tenant-configured endpoints (SSRF-protected, as in T12).

## 5. Versioning & deprecation

- Breaking changes go to `/api/v2`. v1 is supported for ≥ 2 phases after v2 ships.
- Fields are deprecated with `deprecated: true` in OpenAPI plus a `Deprecation` response header.
- The generated TypeScript client lives in `frontend/src/lib/api/` and is regenerated by `scripts/gen-client`.

## 6. Contract testing

- Schemathesis runs against the OpenAPI spec in CI (fuzzing for 5xx, schema violations and auth bypass).
- The route-permission coverage test enumerates routes and asserts that `x-required-permission` exists.
- The cross-tenant suite (SEC-ISO-01) is generated from the route list.
